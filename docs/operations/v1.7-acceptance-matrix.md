# v1.7 desktop and mobile acceptance matrix

**Status:** release acceptance artifact
**Target release:** v1.7.0
**Workstream:** REL-02 acceptance evidence definition
**Release handoff:** REL-04 consumes this matrix for the release-candidate decision
**Review cadence:** Revalidate when the target release, viewport profiles, or account-fixture mechanism changes
**Automated runner:** Chromium via Playwright

This matrix turns the v1.7 release scope into repeatable browser checks. The
existing end-to-end suites are the automated evidence source; manual checks are
used for responsive layout, map usability, touch targets, and visual collisions
that assertions alone cannot prove.

## Manual evidence protocol

For each viewport, capture the following in the release-candidate record:

1. Load the home page and confirm the primary navigation.
2. Open Forecast and confirm the map, toolbar, tabs, legend, and history controls.
3. Open Discussion and return to Forecast without losing the active scope.
4. Open Monitor and confirm the map, controls, attribution, and source-state presentation.
5. Open Verification and confirm the Forecast Grade heading and primary workspace.
6. On portrait and landscape, inspect for horizontal overflow and clipped controls.
7. On desktop, repeat the critical modal and keyboard interactions without a mouse.
8. Record browser, viewport, account state, commit SHA, timestamp, result, and any issue number.

The evidence record must distinguish a product failure from an unavailable
upstream data source. Empty, stale, malformed, unauthorized, and upstream
failure states should be understandable and must not break the surrounding
workflow.

## Hosted account-state protocol

`localTestAccount=free|premium` is a localhost-only fixture. It must not be
used as evidence for beta or staging because the application intentionally
ignores that query parameter on hosted targets. Hosted runs use dedicated,
non-production test accounts managed for the target environment:

| State | Hosted setup | Evidence requirement |
| --- | --- | --- |
| Signed out | Fresh browser context with no authenticated session | Record the target and commit tested; do not record personal account data |
| Free | Authenticated test account with no active premium entitlement | Record the account alias and entitlement state in the release-candidate record |
| Premium | Authenticated test account with an active test entitlement and any target access required for the row | Record the account alias, entitlement state, and target |
| Expired premium | Test account whose entitlement is canceled or expired while its existing data remains available | Verify read-only and safe-downgrade behavior; record the fixture alias and transition state |
| Disabled target | Target deployment with the relevant registry or capability disabled | Verify fail-closed behavior; this is a deployment fixture, not an account fixture |

The maintainer must provision or reconcile these fixtures through the
environment's existing authentication and entitlement controls before a beta
or staging run. If a hosted fixture is unavailable, the row is blocked rather
than being substituted with `localTestAccount`. Record only an alias, target,
build commit, timestamp, and result—never an email address or UID. Local-only
surfaces such as reusable custom-product management remain covered by the
local suite and are not claimed as hosted capability evidence.

## Automated commands

Run the focused matrix while implementing REL-02:

```sh
pnpm exec playwright test e2e/smoke.spec.ts e2e/navigation.spec.ts e2e/discussion.spec.ts
pnpm exec playwright test e2e/workflows.spec.ts e2e/auto-tstm.spec.ts
pnpm exec playwright test e2e/custom-layers.spec.ts e2e/custom-products.spec.ts
pnpm exec playwright test e2e/ui-interactions.spec.ts
```

Run the complete browser suite for the release candidate:

```sh
pnpm run test:e2e
```

### Local baseline

On 2026-08-10, the complete suite ran against this stack on an isolated Vite
server at `http://localhost:43127` with one Chromium worker:

- **44 passed**
- **2 skipped** (the existing target-specific skips)
- **0 failed**

The run emitted expected local API proxy warnings because the analytics/billing
service was not running. Those warnings did not prevent any browser assertion
from passing. This local baseline is supplemental evidence; the required PR
E2E check and the REL-04 release-candidate record are authoritative. Beta and
staging runs must repeat the same matrix against the hosted services before
production promotion.

## Acceptance decision

The REL-02 acceptance artifact is complete when:

- The complete Playwright suite passes on the stack tip.
- The critical workflow rows above have either automated output or attached manual evidence.
- Portrait and constrained-landscape checks show no horizontal overflow.
- The map remains usable in every required viewport.
- Free, premium, expired-premium, signed-out, and disabled-target behavior is explicit.
- Any discovered release blocker is linked to a focused fix rather than hidden in this documentation PR.
