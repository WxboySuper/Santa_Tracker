# v1.7.0 release notes

**Release line:** v1.7.0  
**Candidate source:** reviewed `main` commit, released as a beta before stable promotion  
**Status:** release-candidate documentation

Version 1.7 is GFC's workflow and learning release. It connects forecast
creation, discussion, monitoring, verification, hosted storage, and reflection
while keeping experimental features behind explicit exposure decisions.

## What is included

- Forecast Grade with source-aware evidence, report-quality checks, spatial and
  probability views, shareable summaries, and premium snapshot support.
- Workflow templates, persistent workflow metadata, scoped discussions and
  drafts, package review, completion flows, lifecycle analytics, and handoff
  guidance.
- Local custom layers and reusable hosted products with category styling,
  snapshots, import/export, owner-scoped storage, and premium enforcement.
- Monitor and custom styles, including built-in Rainfall and Tropical AOI
  catalog entries that do not consume personal product slots.
- Auto-TSTM cached guidance with preview/apply/cancel behavior, stale-result
  protection, cache health reporting, and public-safe unavailable states.
- Optional NDFD temperature and SPC mesoscale-discussion reference layers in
  Monitor with source metadata, valid times, attribution, and bounded caching.
- Safer hosted account deletion, subscription cleanup, hosted-data removal, and
  preservation of local/offline saves.
- Privacy-gated self-hosted analytics, explicit target exposure, emergency
  disable controls, release manifests, staging support, and reviewed release
  workflows.

## User-visible behavior boundaries

Core forecast, discussion, Monitor, Verification, save/load, and export
workflows remain available according to the normal product contract. Premium
continues to fund hosted storage and reusable hosted products; core local
forecasting remains free.

The following surfaces remain rollout-controlled and are not implied to be
production-enabled merely because they appear in v1.7 beta notes:

- Auto-TSTM, Forecast workflow v2, Verification relaunch, and Custom products
  follow their target-specific exposure matrix.
- Tropical workspace and Collaboration room remain disabled until their
  foundations and release criteria are complete.
- NOAA DAT damage points are supplemental prototype evidence, not a replacement
  for official verification sources.
- Monitor reference layers are opt-in and do not become forecast geometry,
  forecast export content, or verification truth.

## Privacy and support notes

- Local forecasts remain on the user's device when no account is used.
- Hosted account data is limited to what is needed for sync, account safety,
  billing, and the hosted product experience.
- Product analytics are optional, disabled by default, cookie-free, and not
  linked to Firebase account identity.
- Sentry is separate error monitoring; it does not use session replay and is
  configured to avoid forecast contents and default personal-identifying data.
- A fixed event-level telemetry retention period has not been adopted; support
  must not promise a fixed deletion window.

See [`v1.7 support and privacy operations`](../operations/v1.7-support-and-privacy.md)
for user-support triage and privacy-request handling.

## Evidence and promotion

The release candidate must link:

- [`v1.7 exposure matrix`](../operations/v1.7-exposure-matrix.md)
- [`v1.7 acceptance matrix`](../operations/v1.7-acceptance-matrix.md)
- The generated exposure report for the tested commit
- Browser, accessibility, and responsive evidence
- Beta/staging Sentry health review
- Rollback and support readiness notes

The reviewed `main` candidate is built as a beta first. Stable promotion then
uses the repository's `Prepare Main Stable Promotion`, stable-line bootstrap,
and `Create Stable Release` workflows. No public production exposure is
inferred from a successful local or beta build alone.
