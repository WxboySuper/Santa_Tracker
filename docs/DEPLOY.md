# Deployment Guide

Production target for Christmas Eve 2026 is **Cloudflare Workers + Static Assets** (`apps/web`, vinext). The **VPS standalone** path remains documented below as **legacy** until the owner completes cutover.

See [ADR 0002](adr/0002-cloudflare-workers-hosting.md) for the hosting decision.

---

## Cloudflare Workers (primary)

### Overview

- **Build/deploy:** vinext (`pnpm --filter @santa-tracker/web build:vinext` / `deploy:vinext`)
- **Public data:** `apps/web/public/data/*.json` (mirrored from `apps/web/data/` via `pnpm santa:publish`)
- **Admin snapshots:** R2 bucket binding `SANTA_SNAPSHOTS` (versioned JSON + active pointer)
- **Auth:** JWT admin cookie (`proxy.ts`), `nodejs_compat` enabled
- **Free-tier safety:** Public `/tracker` and `/data/*` are static assets — they do **not** use `run_worker_first`

### Owner setup (one-time)

1. Create an R2 bucket (suggested name: `santa-tracker-snapshots`).
2. Create a Workers project from this repo; set bindings to match `apps/web/cloudflare.config.ts` and `apps/web/wrangler.toml`:
   - `SANTA_SNAPSHOTS` → R2 bucket
   - `ASSETS` / `VINEXT_KV_CACHE` / `IMAGES` — generated by vinext (KV namespace created on first deploy if required)
3. Set secrets (never commit values):
   - `wrangler secret put SECRET_KEY`
   - `wrangler secret put ADMIN_PASSWORD`
4. Set vars: `ADVENT_ENABLED=true`, `SANTA_STORAGE_BACKEND=r2`
5. First content publish:
   ```bash
   pnpm install
   pnpm santa:publish          # mirror JSON into public/data for static serving
   pnpm santa:publish:remote     # optional: upload active snapshots to R2 (requires API token)
   ```
6. Deploy manually via GitHub Actions workflow **Deploy Cloudflare Workers (manual)** (`deploy-cloudflare-workers.yml`) using repository secret `CLOUDFLARE_API_TOKEN`.

### Local preview

```bash
pnpm --filter @santa-tracker/web dev:vinext   # vinext dev server (port 3001)
# or after build:
pnpm --filter @santa-tracker/web build:vinext
pnpm --filter @santa-tracker/web start:vinext
```

Local admin/route storage uses the filesystem adapter under `apps/web/data/.versioned/` (no R2 required).

### Cache headers

Published JSON is served with `Cache-Control: public, max-age=900, stale-while-revalidate=3600` (`next.config.mjs` headers + `public/_headers`).

## VPS standalone (legacy)

> **Legacy:** Release deploy via `.github/workflows/deploy-on-release.yml` until Cloudflare production is verified.

### Overview

- Next.js `output: "standalone"` (`apps/web`)
- Node.js 22+; artifact at `apps/web/.next/standalone/server.js`
- Data files at `apps/web/data/` with versioned snapshots via the snapshot store (filesystem backend locally on VPS)

### File ownership

```
/srv/santa-tracker/
├── releases/20251201-120000/
│   ├── server.js
│   ├── .next/static/
│   ├── public/
│   ├── data/
│   └── .env (600)
├── current -> releases/...
```

### Environment (both targets)

- `SECRET_KEY` — JWT signing (HS256)
- `ADMIN_PASSWORD` — login only
- `ADVENT_ENABLED` — `true` / `false`
- `SANTA_ROUTE_PATH` / `ADVENT_CALENDAR_PATH` — optional overrides (VPS)
- `SANTA_STORAGE_BACKEND` — `filesystem` (default dev/VPS) or `r2` (Workers)
- `SANTA_DATA_ROOT` — optional data directory override
